## 9. 附加排查：旧 `out.webm` 预览发黑 vs 本次输出发白

用户反馈：同目录旧文件 `out.webm`（Python 环境产出）预览显示**黑背景**，本次 `tgtv_out_vp9.webm` 显示**白背景**。

### 9.1 结构对比：两者等价

| 项 | `out.webm` | `tgtv_out_vp9.webm` |
|---|---|---|
| 编码 / 格式 | VP9 Profile 0, `yuv420p`(原生读出) | 同 |
| 尺寸 / 时长 | 1000×1000 / 2.85s | 同 |
| `AlphaMode` (EBML 0x53C0) | **1**（声明 alpha） | **1**（声明 alpha） |
| alpha 掩码 vs 源 GIF | 平均绝对差 0.00，透明像素数差 0 | 同 |
| 可见区 RGB 平均绝对差 | 2.92（最大 53） | 2.92（最大 53） |

**两者在编码、容器、alpha 掩码、可见内容上完全等价。** 差异只有一个维度。

### 9.2 真正的差异：透明区底层的 RGB

| 文件 | alpha=0 像素的 RGB | 判定 |
|---|---|---|
| `out.gif`（源） | (255,255,255)，占比 100% | 白 |
| `tgtv_out_vp9.webm` | (254,254,254)，(255,255,255) 占 99.7% | **白（与源一致）** |
| `out.webm` | (0,0,0)，占比 99.8% | **黑（与源不符）** |

不透明区 RGB 均值三者均为 (65~66, 73~74, 70~71)，未被影响。

### 9.3 成因

alpha 分布为**二值**（全不透明 28000 / 全透明 972000 / 半透明 0）。在此前提下：

- 白色 × (0/255) = 黑色；
- 不透明像素 × (255/255) = 原值不变。

实测结果与**预乘 alpha（premultiply）**或「先合成到黑底再保留 alpha」完全吻合：透明像素 RGB 被清零，不透明像素分毫未动。这是 Python 侧图像库（Pillow / imageio / moviepy 一类）处理 RGBA 时的典型行为。

> 说明：因本夹具 alpha 为纯二值、无半透明像素，**预乘**与**合成到黑底**两种成因在结果上不可区分。二者属于同一类问题。

### 9.4 影响范围（重要）

在**正确支持 alpha 的播放器**中，合成公式为 `src_rgb × a + bg × (1-a)`；当 `a=0` 时结果为背景色，与 `src_rgb` 无关——**两个文件看起来都应该是透明的，没有区别**。

黑/白差异**只在忽略 alpha 的预览器中出现**，此时显示的是透明区垫底的那层 RGB。

因此：

- 本次 skill 输出保留了源 GIF 透明区的原始 RGB（白），是**straight（非预乘）alpha**，与源一致；
- 旧 `out.webm` 的透明区 RGB 被破坏为黑。两者 alpha 通道本身都完好。

### 9.5 结论

**不是 skill 的 bug，本次输出反而更忠实于源。** 若在忽略 alpha 的预览器下希望呈现黑底，需要主动做预乘，这超出本 skill 的职责范围（skill 明令禁止猜背景色与合成）。

### 11.3 重要：§4.2 的 `YMIN<255` 断言在 >8-bit alpha 上误报

ProRes 4444 首轮报 `YMIN=256 YMAX=3760 → FAIL`。实测证伪：

- 8-bit rgba 视图：透明区 alpha **=0**、不透明区 **=255**、`alpha==0` 像素数 **972000 = 源逐像素完全一致**；
- 带 / 不带 `-alpha_bits 8` 结果完全相同。

根因：`prores_ks` 读取为 `yuva444p12le`，`alphaextract` 输出 **gray16**，`signalstats` 在 16 位域报值，8 位阈值必然失效。

**修复方案（实测普适）**：在 `alphaextract` 后插入 `format=gray` 归一化到 8 位。

| 文件 | 现状 `alphaextract,signalstats` | 修正 `alphaextract,format=gray,signalstats` |
|---|---|---|
| VP9 CRF30 / lossless / VP8 | YMIN=0 PASS | YMIN=0 PASS |
| **ProRes 4444** | **YMIN=256 FAIL** | **YMIN=0 PASS** |
| HAP Alpha | YMIN=0 PASS | YMIN=0 PASS |
| 黑底 MP4 | 无 YMIN/YMAX（预期） | 同 |

建议把 §4.2 命令改为 `-vf alphaextract,format=gray,signalstats`，或对 >8 位按 `(2^depth - 1)` 归一化阈值。

### 11.4 观察：跨格式"透明底层 RGB"不一致

新模板只给 VP8/VP9 加了黑色归一化，**ProRes 4444 与 HAP Alpha 仍保留源 GIF 的白底**。因此在忽略 alpha 的预览器中：VP9/VP8 显黑，ProRes/HAP 显白。

在正确合成 alpha 的播放端，两者视觉一致（均透明）。但若用户依赖忽略 alpha 的预览器判断，会得到互相矛盾的结论。建议在 SKILL.md 中明示该差异是有意为之还是遗漏。

## 10. 过程中发现的两个测试脚本 bug（已修正，与 skill 无关）

1. `select=eq(n\,N)` 过滤器在本环境输出为空，导致首轮比对全部返回空串 MD5（`d41d8cd9...`）而**假性全绿**。改用「解码 N+1 帧取末帧」绕过。
2. 按 `*.webm` 通配分配解码器，把 VP9 文件交给了 VP8 解码器，产生零输出。

> 教训：逐帧比对类断言必须**先断言字节数**，否则空输出会伪装成"一致"。
