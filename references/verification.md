# 只用 FFmpeg 验证输出

## 1. 两层验证

转换后必须完成：

1. 完整解码所有视频帧；
2. 从实际解码结果中提取 alpha 平面。

完整解码发现损坏、截断和解码器错误；`alphaextract` 证明解码链路中存在 alpha 平面。

## 2. WebM 的特殊点

VP8/VP9 WebM 的 alpha 可存放在 BlockAdditional 中。某些原生探测或解码路径只显示颜色平面，因此验证时必须显式选择：

```text
VP9: -c:v libvpx-vp9
VP8: -c:v libvpx
```

不能仅凭日志中的 `pix_fmt=yuv420p` 判定透明丢失。

## 3. 验证边界

只使用 `ffmpeg`、不使用 ffprobe 或脚本解析时，可以可靠证明：

- 文件能够完整解码；
- 目标解码器能够提供 alpha 平面。

它不能自动给出结构化的：

- 输入/输出逐帧 PTS 差异；
- alpha 像素逐点相等；
- 帧数和总时长 JSON 断言。

这些属于开发回归测试，而不是每次用户转换的运行时依赖。严格无损交付需要额外做逐帧 hash 或像素比较。

## 4. 播放兼容性不是编码正确性

`alphaextract` 成功只说明文件中存在可解码 alpha。目标浏览器、播放器或剪辑软件仍可能不支持该容器/编码组合。必须结合最终投放端选择格式。
