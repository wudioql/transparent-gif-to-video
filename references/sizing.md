# 质量与体积

体积由画布、帧数、变化区域、颜色和编码器决定，不能从 GIF 大小直接推断。

> **测量基线（2026-10-03，Phase 7 校准）**：下述结论的数字基线为 Python 新栈
> （PyAV 18.1.0 / libavcodec 62.x，即 `tgtv` 包自身），并与 ffmpeg 7.0.2 CLI
> 同参数对照等价（差异 ≤0.3 dB / ≤2% 像素计数，见
> `test-reports/2026-10-03-sizing-calibration.md`）。校准素材与脚本：
> `tests/calibrate_sizing.py`（1000×1000 / 95 帧 / 二值 alpha / 高边缘密度合成素材）。
> 旧数字（BtbN ffmpeg 9.0.1 静态包，真实素材）保留在本页末尾作历史基线。

| 输出 | 默认起点 | 备注 |
|---|---|---|
| VP9 WebM | `crf 30`（注册表默认） | **唯一默认起点**；不要再往上调 CRF，见下 |
| VP9 lossless | `lossless 1` | 很大；仍为 `yuva420p`（4:2:0 表示限制，非 RGBA 逐点保证） |
| VP8 | `crf 30` | 非默认；实测明显劣于 VP9，仅在明确兼容需求时使用 |
| ProRes 4444 | profile 4444 + 8-bit alpha | 高码率编辑母版 |
| PNG/qtrle/FFV1 | 无损 | 可能显著大于 VP9 |
| 黑底 H.264 | CRF 20, preset slow | 不含 alpha；仅明确选择后使用 |

（HAP Alpha 已随 Phase 0 决策从矩阵移除：PyAV wheel 不含 hap encoder，不偷换格式。）

## CRF 取值边界：仅限 VP8/VP9 WebM

**CRF 是逐编码器的相对刻度，不可跨平台类比。** 下面的 30 只适用于 libvpx 家族；黑底 MP4（libx264）用 CRF 20，两者数字不互通。同一 libvpx 家族内部也不可直接类比——实测同为 CRF 30，VP8 的可见区 PSNR 比 VP9 低约 7 dB（校准素材 6.9 dB，CLI 对照 7.5 dB；旧真实素材 7.6 dB），且可见晕环高四个数量级。

CRF 越高 = 码率越低 = 画质越差。对**带 alpha 的二值 GIF 素材**，把 VP8/VP9 的 CRF 从 30 提到 40 会同时损伤 RGB 和 alpha 平面。新栈校准实测（1000×1000 / 95 帧 / 高边缘密度二值 alpha 合成素材；tgtv = PyAV 18.1.0，cli = ffmpeg 7.0.2 同参数对照）：

| 候选 | 栈 | 体积 | 可见区 PSNR | 95 帧半透明总量 | 其中可见晕环(32–223) |
|---|---|---:|---:|---:|---:|
| VP9 CRF 30 | tgtv | 0.55 MB | **28.5 dB** | 2,274,597 | **7** |
| VP9 CRF 30 | cli | 0.56 MB | 28.8 dB | 2,289,369 | 3 |
| VP9 CRF 40 | tgtv | 0.33 MB | 27.3 dB | 3,956,043 | 2,596 |
| VP9 CRF 40 | cli | 0.33 MB | 27.5 dB | 3,931,948 | 2,515 |
| VP8 CRF 30 | tgtv | 0.23 MB | 21.6 dB | 3,195,588 | 58,961 |
| VP8 CRF 30 | cli | 0.23 MB | 21.2 dB | 3,128,242 | 62,062 |
| VP8 CRF 40 | tgtv | 0.23 MB | 21.6 dB | 2,987,057 | 59,873 |
| VP8 CRF 40 | cli | 0.23 MB | 21.2 dB | 3,128,242 | 62,062 |

三点结论（与旧基线一致，新栈复现）：

1. **CRF 40 省下的体积不值。** VP9 CRF 40 体积省 40%，代价是 alpha 平面新增约 168 万个半透明像素（其中可见晕环从个位数涨到 2.6 千）——源素材是纯二值 alpha（半透明 = 0），这些就是实打实的边缘晕环。
2. **CRF 已饱和。** VP8 从 CRF 30 到 CRF 40 体积一点不变（0.23→0.23 MB，旧基线也是只差 0.5%），再往上调没有任何收益，只有损失。
3. **别为了体积退回 VP8。** VP8 的 PSNR 落差 ~7 dB 之外，**可见晕环比 VP9 多四个数量级**（58,961 vs 7 px）——alpha 边缘的损伤才是 VP8 的致命伤（旧基线真实素材上表现为半透明总量高一个数量级：9.2M vs 698K，幅度与素材边缘密度相关，方向一致）。

因此：**VP9 WebM CRF 30 是 WebM 侧唯一默认值。** 只有当用户明确要求更小体积并提出可接受的画质折损时，才讨论其他档位；否则不要主动上调 CRF，也不要把 CRF 40 列为常规备选。需要更高保真时走 VP9 lossless / ProRes 4444 / FFV1。

MP4 侧没有任何 CRF 自由度的默认讨论空间：黑底 H.264 固定 CRF 20 / preset slow，用户明确选择后才使用。

VP8/VP9 的透明 RGB 黑色归一化可能改变压缩统计，但不改变二值 alpha；以新栈（`tgtv`，PyAV 18.1.0）实测体积和视觉结果为准，CLI 基线仅作迁移期对照。
