# 体积与质量控制

不要只用一个固定“MB 锚点”预测所有素材。实际编码由像素数、帧率、帧间变化、色数、透明比例和编码器共同决定。

## 1. 先做小样本实测

脚本目前不做虚假的单点体积承诺。建议：

1. `inspect` 记录尺寸、帧数、时长和 alpha 分布。
2. 使用目标 codec 转一次完整素材或短裁样本。
3. 记录实际输出体积和 `verify` 结果，再调整 CRF。

恒定码率倾向的 ProRes/qtrle 按“像素数 × 帧数”近似线性；PNG/FFV1 受画面复杂度影响；VP8/VP9/H.264 对运动量和纹理更敏感。

## 2. 参数建议

| 路径 | 起点 | 调整方向 |
|---|---|---|
| VP9 alpha | `--crf 30` | 有渐变/细线时降至 24–26；越低体积越大 |
| VP9 alpha 无损 | `--lossless` | 只在逐像素一致重要时用 |
| VP8 alpha | `--crf 30` | 体积通常小于 VP9，但质量/效率不同 |
| H.264 不透明 | `--crf 20` | 复杂渐变可降到 16–18；平坦动画可提高到 22 |
| `--cpu-used` | `2` | 更大更快但压缩效率通常变差 |
| H.264 `--preset` | `slow` | 有时间可更慢；只影响速度/效率，不改变背景逻辑 |
| `--bleed-edges` | `0` | 开到 2 约 +3% 体积；只在浅色背景上的半透明素材值得 |

## 3. 质量判断

- 二值 alpha 源若输出出现大量半透明像素，优先降低 CRF 或改无损。
- 透明输出要用 `verify --expect alpha`，不以某个播放器截图为唯一依据。
- 不透明输出要用 `verify --expect opaque`，并在目标背景上观察边缘；`auto-edge` 只能证明它检测到了单色透明边缘，不能证明该颜色就是投放端想要的页面背景。
